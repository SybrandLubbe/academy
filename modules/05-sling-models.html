Sling Models

A Sling Model turns a Resource into a typed Java object you can use directly in a template or a servlet — the bridge between the repository tree from module 2 and the components you'll build in module 8.

What you'll learn

  • The @Model annotation, and what "adaptable" means
  • The injectors you'll use constantly: @ValueMapValue, @ChildResource, @SlingObject, @OSGiService
  • Required vs. optional injection, and why adaptTo() sometimes silently returns null
  • Deriving values with @PostConstruct
  • Exposing a model as JSON with @Exporter

Why Sling Models exist

Before models, components read content directly from a ValueMap or walked a Resource by hand inside the render script itself, mixing repository access with presentation logic. A Sling Model moves that access into a plain, testable Java class — the template asks the model for a typed value (a String, a List, a boolean) instead of reaching into the repository itself.

Anatomy of a model

A model declares what it can adapt from and, usually, which resource type it's tied to:

TeaserModel.javapackage biz.netcentric.academy._05;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Exporter;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ChildResource;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;

import javax.annotation.PostConstruct;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/teaser",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
@Exporter(name = "jackson", extensions = "json")
public class TeaserModel {

    @ValueMapValue
    private String title;

    @ValueMapValue
    private String description;

    @ChildResource
    private Resource image;

    private String shortDescription;

    @PostConstruct
    protected void init() {
        if (description != null && description.length() > 80) {
            shortDescription = description.substring(0, 80).trim() + "…";
        } else {
            shortDescription = description;
        }
    }

    public String getTitle() {
        return title;
    }

    public String getShortDescription() {
        return shortDescription;
    }

    public boolean hasImage() {
        return image != null;
    }
}

The adaptables value matters: Resource.class works wherever you have a resource — including adapting from inside another model — while SlingHttpServletRequest.class is only available during an actual request, but gives you request-specific things a bare resource can't, like selectors or request parameters.

Injectors, briefly

Each field's annotation tells Sling Models where to pull the value from. @ValueMapValue reads a property off the resource. @ChildResource resolves a named child node as a Resource (or adapts it straight into another model). @SlingObject injects framework objects you already know — Resource, ResourceResolver, SlingHttpServletRequest. @OSGiService injects a service from the registry, exactly like @Reference did for OSGi components in module 4 — models can depend on services too.

Required vs. optional injection

By default, every injected field is required: if Sling can't find a value for it, the whole model fails to instantiate and resource.adaptTo(TeaserModel.class) returns null — not a half-populated object. Setting defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL at the class level (as above) flips that default, which is usually what you want for content fields that are genuinely optional, like a teaser's image.

Common pitfall adaptTo() returning null with no exception is the single most common Sling Models debugging trap. It almost always means a required field had nothing to inject. Enable debug logging on org.apache.sling.models.impl in the Felix console to see exactly which field failed.

Exposing a model as JSON

@Exporter(name = "jackson", extensions = "json") is what made the .model.json selector work in the Java Primer's exercises 3 and 5 — it's the same mechanism, now with the rest of the picture filled in: the model's getters become JSON fields, and anything you didn't expose with a getter simply isn't in the output.

Using a model in a template

Module 6 covers this properly, but the shape is short enough to preview here:

teaser.html<div data-sly-use.teaser="biz.netcentric.academy._05.TeaserModel">
    <h2>${teaser.title}</h2>
    <p>${teaser.shortDescription}</p>
</div>
Try it Extend StudentModel from the Java Primer's exercise 3 with a @PostConstruct method that builds a fullName field from name and surname, then confirm it shows up at /content/academy/student.model.json.
