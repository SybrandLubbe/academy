HTL (Sightly) Templating

HTL is AEM's templating language, designed so a malformed or malicious value can't execute as code — security is built into the syntax itself, not bolted on afterward.

What you'll learn

  • Bringing data into a template with data-sly-use
  • data-sly-test and data-sly-list for conditionals and loops
  • Why HTL escapes output differently depending on where it sits
  • The difference between data-sly-resource and data-sly-include
  • Writing comments that never reach the browser

Why HTL, not JSP

AEM's older templating option, JSP, allowed arbitrary Java embedded directly in markup — powerful, but it made output escaping the developer's responsibility on every single line, and a single missed escape was a cross-site-scripting bug waiting to happen. HTL deliberately removes that option: there are no scriptlets, expressions can't call arbitrary methods, and the markup can be statically analyzed before it ever runs.

Bringing in data: data-sly-use

data-sly-use instantiates a Sling Model (or a legacy "Use-API" class) and binds it to a name you can reference in expressions:

/aem-academy/ui.apps/src/main/content/jcr_root/apps/academy/components/teaser/teaser.html (academy.ui.apps)<div data-sly-use.teaser="biz.netcentric.academy._05.TeaserModel">
    <h2>${teaser.title}</h2>
    <p>${teaser.shortDescription}</p>
</div>

${ } expressions are deliberately limited: you can read a property (teaser.title), index into a list or map, and use a handful of operators — but you can't call a method with arguments. Any logic that needs parameters belongs in the model, not the template.

Conditionals and loops

The next two snippets are syntax illustrations rather than a continuation of the exact teaser.html above — hasImage and relatedLinks would need adding to TeaserModel first if you want to build them for real:

HTL syntax — conditionals and loops<div data-sly-test="${teaser.hasImage}">
    <img src="${teaser.image.path}" alt="${teaser.title}" />
</div>

<ul data-sly-list.item="${teaser.relatedLinks}">
    <li>${item.index}: ${item.title}</li>
</ul>

data-sly-test removes the element entirely when the expression is falsy — not just hides it with CSS. data-sly-list repeats the element once per item and gives you loop helpers like item.index, item.count, and item.first/item.last for free. data-sly-repeat works the same way but keeps the wrapping element itself in the output once per item, rather than only its children.

Context-aware escaping

HTL looks at where an expression sits in the markup and escapes its output accordingly: inside text content it HTML-escapes, inside an href it URI-escapes, inside a <script> block it applies JavaScript string escaping. You don't choose the escaping — HTL infers it from context, which is exactly what removes the human error JSP was prone to.

You can override the inferred context explicitly when needed, for example forcing URI escaping on a value HTL can't otherwise classify:

explicit context<a href="${teaser.linkPath @ context='uri'}">Read more</a>
Common pitfall HTL supports context='unsafe', which disables escaping entirely. It exists for rare cases where you're deliberately outputting pre-sanitized markup — never reach for it just to make a value "work." It removes the exact protection HTL was built to provide.

Including vs. rendering another resource

data-sly-resource renders a child resource through the full Sling resolution pipeline from module 3 — selectors, resourceType inheritance, the works — exactly as if that resource had been requested directly:

data-sly-resource<div data-sly-resource="${'image' @ resourceType='academy/components/image'}"></div>

data-sly-include is lighter weight: it pulls in another script's raw markup output within the same component, without a separate resource-resolution pass — useful for splitting one component's markup across files, not for rendering child components.

Comments

A normal HTML comment (<!-- -->) is sent to the browser like any other markup. An HTL comment is stripped server-side and never leaves AEM:

server-side comment<!--/* TODO: replace with a real empty-state once design has one */-->
Try it Build teaser.html against the TeaserModel from module 6, using data-sly-test so the whole component renders nothing when title is empty — confirm by emptying the title on your test content node and reloading the page.
