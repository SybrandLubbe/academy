Custom Components Workshop

Two complete components, built from an empty starting point: an extended Image component that reads and displays a DAM asset's metadata, and a Weather component that geocodes an author-entered city and pulls live conditions from a free public API.

What you'll learn

  • Exactly where in an AEM project's Maven structure new Java, component, and dialog files belong
  • Extending a Core Component by resource type inheritance instead of building from scratch
  • Reading DAM asset metadata from a Sling Model
  • Calling an external REST API from a Sling Model, and why that's a pattern to use carefully

Before you start: where this code lives

This uses the exact /aem-academy project structure from module 00's "Before you start" — go back there for the full picture if you skipped it. As a reminder: Java goes in core (academy.core), anything an author drags onto a page goes in ui.apps (academy.ui.apps), and every path below is given in full from /aem-academy, the project root.

Mental model Running mvn clean install -PautoInstallSinglePackage from /aem-academy builds every module and deploys the whole thing to localhost:4502 in one command. You won't run javac or copy files into the repository by hand at any point.

Both components below assume your project already depends on the AEM Core Components (the project archetype includes this by default as core.wcm.components.core). If a Core Components class doesn't resolve when you build, add that dependency to /aem-academy/core/pom.xml (academy.core) before continuing.

Component 1 — Image with Metadata

Rather than building an image component from scratch, we extend the Core Components Image component the same way module 3 described overlays working: by pointing resourceSuperType at it. We get the existing image-picking dialog, accessibility markup, and responsive image handling for free, and add one thing on top — a small metadata panel read from the underlying DAM asset.

Step 1 — the Java Sling Model

Save this as a brand new file at:

/aem-academy/core/src/main/java/biz/netcentric/academy/components/imagemetadata/ImageMetadataModel.java (academy.core)package biz.netcentric.academy.components.imagemetadata;

import com.adobe.cq.wcm.core.components.models.Image;
import com.day.cq.dam.api.Asset;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.api.resource.ResourceResolver;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.Self;
import org.apache.sling.models.annotations.injectorspecific.SlingObject;
import org.apache.sling.models.annotations.via.ResourceSuperType;

import javax.annotation.PostConstruct;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/imagemetadata",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class ImageMetadataModel {

    @Self
    @org.apache.sling.models.annotations.via.Via(type = ResourceSuperType.class)
    private Image coreImage;

    @SlingObject
    private ResourceResolver resourceResolver;

    private String width;
    private String height;
    private String format;
    private String cameraModel;

    @PostConstruct
    protected void init() {
        if (coreImage == null || coreImage.getFileReference() == null) {
            return;
        }
        Resource assetResource = resourceResolver.getResource(coreImage.getFileReference());
        Asset asset = assetResource != null ? assetResource.adaptTo(Asset.class) : null;
        if (asset == null) {
            return;
        }
        width = asset.getMetadataValue("tiff:ImageWidth");
        height = asset.getMetadataValue("tiff:ImageLength");
        format = asset.getMetadataValue("dc:format");
        cameraModel = asset.getMetadataValue("tiff:Model");
    }

    public String getSrc() {
        return coreImage != null ? coreImage.getSrc() : null;
    }

    public String getAlt() {
        return coreImage != null ? coreImage.getAlt() : null;
    }

    public String getWidth() {
        return width;
    }

    public String getHeight() {
        return height;
    }

    public String getFormat() {
        return format;
    }

    public String getCameraModel() {
        return cameraModel;
    }

    public boolean hasMetadata() {
        return width != null || format != null;
    }
}
📖 Why this code?

This model demonstrates extending a Core Component and using the AEM Asset API to read metadata from DAM assets.

  • implements Image — the Core Components Image interface. By implementing this interface, the model can be used anywhere a Core Image model is expected, and inherits the interface contract for properties like getSrc() and getAlt().
  • @Via(type = ResourceSuperType.class) — injects the Core Components' own Image model for this resource, giving you src, alt, and link resolution without reimplementing them.
  • asset.getMetadataValue("tiff:ImageWidth") — reads standard EXIF/TIFF metadata from the DAM asset. The tiff: namespace prefix is standard EXIF nomenclature — tiff:ImageWidth, tiff:ImageLength, tiff:Model (camera model) are common fields.

@Self @Via(type = ResourceSuperType.class) is the key line: it adapts the same resource to the core Image component's own model first, then hands you that fully-built object to read from — rather than re-implementing image rendering yourself. Module 8 already covered this composition pattern in depth; this is it in practice.

Create the component folder and its definition file:

📖 Why this code?

The component definition for ImageMetadata — the XML that registers it as a component and declares it inherits from Core Image.

  • sling:resourceSuperType="core/wcm/components/image/v3/image" — this line is why the component has a dialog without any _cq_dialog folder of its own. Sling's script resolution walks up the super type chain — finding no dialog here, it uses the Core Image's dialog. Authors get the full image picker with no extra work.
  • This also means Sling's render script resolution falls back to Core Image's scripts for anything you don't override — the component inherits responsive image breakpoints, lazy loading, and the empty placeholder in the editor.

📖 Why this code?

The HTL template for the ImageMetadata component — notice how thin it is, because all logic lives in the model.

  • data-sly-use.metadata="...ImageMetadataModel" — adapts the resource to the model. All image src/alt resolution and all metadata reading happens inside the model's @PostConstruct.
  • data-sly-test="${metadata.hasMetadata}" — the entire metadata block is absent from the HTML if the asset has no EXIF data (e.g. a manually cropped screenshot). The template makes zero decisions about when this is or isn't relevant — that logic is in hasMetadata().
Mental model There's no _cq_dialog folder in this component at all — and that's deliberate. Since we didn't provide one, Sling's resourceType resolution from module 3 walks up to resourceSuperType and uses the core Image component's own dialog instead. The image-picking UI an author sees is the exact same one the standard Image component uses.

Build and deploy. Verify the ImageMetadata component is ACTIVE before testing in the page editor. The activation step (allowing the component in a template policy) is separate from deployment.

Once it's allowed and deployed, open any page in the AEM editor, drag the new Image with Metadata component from the component browser (it sits in the "Academy Training" group) into a paragraph system, and pick any asset from /content/dam the same way you would with a normal Image component. If the asset has EXIF/TIFF metadata (most camera photos do; a plain screenshot usually won't), the dimensions, format, and camera model appear underneath it.

Try it with students Upload two assets to /content/dam/academy — one photo straight from a phone camera, one plain screenshot or graphic — and place both on a page with this component. Compare what renders for each, and ask students to predict which metadata fields will be empty before they look.

Component 2 — Weather

This component combines two patterns: a Sling Model that renders author-configured weather server-side on page load, and a Sling Servlet that any visitor (or the author in preview mode) can call interactively by typing a city name and clicking a button. The result renders in a table — no page reload required. It uses the same free Open-Meteo API as before, with more fields and the newer current= parameter format.

Two layers, one component The Sling Model handles the initial server-rendered state (city from the author dialog). The Servlet handles interactive look-ups after the page loads. Both layers call the same Open-Meteo APIs and return the same fields — the Servlet just returns JSON instead of rendering HTML, letting JavaScript update the table without a full page refresh.

Step 1 — Updated Sling Model

The model gains new fields (apparent temperature, humidity, wind direction, precipitation, WMO conditions) by switching from current_weather=true to the newer current= parameter.

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherModel.java (academy.core)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import javax.annotation.PostConstruct;
import javax.json.Json;
import javax.json.JsonArray;
import javax.json.JsonObject;
import java.io.IOException;
import java.io.StringReader;
import java.net.URI;
import java.net.URLEncoder;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.util.Map;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/weather",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class WeatherModel {

    private static final Logger LOG = LoggerFactory.getLogger(WeatherModel.class);
    static final HttpClient HTTP_CLIENT = HttpClient.newHttpClient(); // package-visible for servlet

    // WMO weather interpretation codes → human-readable label
    // Full table: https://open-meteo.com/en/docs#weathervariables
    private static final Map<Integer, String> WMO_CODES = Map.ofEntries(
        Map.entry(0,  "Clear sky"),
        Map.entry(1,  "Mainly clear"), Map.entry(2,  "Partly cloudy"), Map.entry(3,  "Overcast"),
        Map.entry(45, "Foggy"),        Map.entry(48, "Depositing rime fog"),
        Map.entry(51, "Light drizzle"),Map.entry(53, "Moderate drizzle"),Map.entry(55, "Dense drizzle"),
        Map.entry(61, "Slight rain"),  Map.entry(63, "Moderate rain"),   Map.entry(65, "Heavy rain"),
        Map.entry(71, "Slight snow"),  Map.entry(73, "Moderate snow"),   Map.entry(75, "Heavy snow"),
        Map.entry(80, "Slight showers"),Map.entry(81,"Moderate showers"),Map.entry(82,"Violent showers"),
        Map.entry(95, "Thunderstorm"),
        Map.entry(96, "Thunderstorm with hail"), Map.entry(99, "Heavy thunderstorm with hail")
    );

    @ValueMapValue private String city;
    @ValueMapValue private String country;

    // ── Weather fields — expanded vs the original ─────────────────────────
    private String resolvedLocation;
    private Double temperature;
    private Double apparentTemperature;   // "feels like"
    private Double windSpeed;
    private Integer windDirection;        // degrees 0-360
    private Integer humidity;             // percentage
    private Double  precipitation;        // mm
    private Integer weatherCode;
    private String  conditions;           // human-readable WMO description
    private String  error;

    @PostConstruct
    protected void init() {
        if (city == null || city.isBlank()) return;
        try {
            double[] coords = geocode(city, country);
            fetchCurrentWeather(coords[0], coords[1]);
        } catch (Exception e) {
            LOG.warn("Weather lookup failed for city={}, country={}", city, country, e);
            error = "Could not load weather for \u201c" + city + "\u201d.";
        }
    }

    // Package-visible so WeatherSearchServlet can reuse both methods
    double[] geocode(String cityName, String countryName) throws IOException, InterruptedException {
        String query = URLEncoder.encode(cityName, StandardCharsets.UTF_8);
        String url   = "https://geocoding-api.open-meteo.com/v1/search?name=" + query + "&count=10";
        JsonObject body    = fetchJson(url);
        JsonArray  results = body.getJsonArray("results");
        if (results == null || results.isEmpty()) {
            throw new IOException("No geocoding results for \"" + cityName + "\"");
        }

        JsonObject match = results.getJsonObject(0);
        if (countryName != null && !countryName.isBlank()) {
            for (int i = 0; i < results.size(); i++) {
                JsonObject candidate = results.getJsonObject(i);
                if (countryName.equalsIgnoreCase(candidate.getString("country", ""))) {
                    match = candidate; break;
                }
            }
        }

        resolvedLocation = match.getString("name") + ", " + match.getString("country", "");
        return new double[]{
            match.getJsonNumber("latitude").doubleValue(),
            match.getJsonNumber("longitude").doubleValue()
        };
    }

    void fetchCurrentWeather(double lat, double lon) throws IOException, InterruptedException {
        // New Open-Meteo current= format — returns more fields than current_weather=true
        String url = String.format(
            "https://api.open-meteo.com/v1/forecast" +
            "?latitude=%s&longitude=%s" +
            "&current=temperature_2m,apparent_temperature,wind_speed_10m," +
            "wind_direction_10m,relative_humidity_2m,weather_code,precipitation",
            lat, lon);
        JsonObject body    = fetchJson(url);
        JsonObject current = body.getJsonObject("current");

        temperature         = current.getJsonNumber("temperature_2m").doubleValue();
        apparentTemperature = current.getJsonNumber("apparent_temperature").doubleValue();
        windSpeed           = current.getJsonNumber("wind_speed_10m").doubleValue();
        windDirection       = current.getInt("wind_direction_10m");
        humidity            = current.getInt("relative_humidity_2m");
        weatherCode         = current.getInt("weather_code");
        precipitation       = current.getJsonNumber("precipitation").doubleValue();
        conditions          = WMO_CODES.getOrDefault(weatherCode, "Unknown (code " + weatherCode + ")");
    }

    static JsonObject fetchJson(String url) throws IOException, InterruptedException {
        HttpRequest req = HttpRequest.newBuilder(URI.create(url)).GET().build();
        HttpResponse<String> resp = HTTP_CLIENT.send(req, HttpResponse.BodyHandlers.ofString());
        return Json.createReader(new StringReader(resp.body())).readObject();
    }

    // ── Public getters ────────────────────────────────────────────────────
    public String  getCity()                { return city; }
    public String  getResolvedLocation()    { return resolvedLocation; }
    public Double  getTemperature()         { return temperature; }
    public Double  getApparentTemperature() { return apparentTemperature; }
    public Double  getWindSpeed()           { return windSpeed; }
    public Integer getWindDirection()       { return windDirection; }
    public Integer getHumidity()            { return humidity; }
    public Double  getPrecipitation()       { return precipitation; }
    public String  getConditions()          { return conditions; }
    public String  getError()               { return error; }
    public boolean isAvailable()            { return temperature != null; }

    // Helper map exposed for the Servlet to reuse
    static Map<Integer, String> getWmoCodes() { return WMO_CODES; }
}
📖 Why this code?

The model gains fields and a WMO code map, but the core pattern from modules 6 and 7 is unchanged — @ValueMapValue for dialog input, @PostConstruct for derived values, thin getters for HTL.

  • Map.ofEntries(Map.entry(...)) — creates a static, immutable WMO code lookup table. Map.of() supports only up to 10 entries; Map.ofEntries() has no limit. static final means it's allocated once when the class loads, not once per request.
  • &current=temperature_2m,apparent_temperature,... — the newer Open-Meteo API parameter. The response is now under "current" (not "current_weather") with underscore-suffixed keys like temperature_2m (temperature at 2 metres). This format supports many more variables than the legacy endpoint.
  • static on HTTP_CLIENT, fetchJson(), geocode(), and fetchCurrentWeather() — the Servlet needs to reuse these without creating a WeatherModel instance (which would need a Resource to adapt from). Making them package-visible statics lets the Servlet call them directly.
  • \u201c and \u201d — Unicode for curly quotes in the error message. Using literal curly quotes in Java strings risks encoding issues if the source file is not saved as UTF-8; Unicode escapes are always safe.

Step 2 — WeatherSearchServlet

This is the AJAX endpoint the JavaScript calls when a user submits the search form. It accepts city and country as GET parameters, calls the same Open-Meteo APIs via the shared methods in WeatherModel, and writes a JSON response. This is the path-based servlet pattern from module 10 — registered at /bin/academy/weather, not tied to any content node.

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherSearchServlet.java (academy.core)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.servlets.SlingSafeMethodsServlet;
import org.osgi.service.component.annotations.Component;

import javax.json.Json;
import javax.json.JsonObjectBuilder;
import javax.servlet.Servlet;
import javax.servlet.ServletException;
import java.io.IOException;
import java.util.Map;

/**
 * AJAX endpoint for interactive city lookups.
 * GET /bin/academy/weather?city=London&country=UK
 * Returns JSON with current conditions, or {"error":"..."} on failure.
 */
@Component(service = Servlet.class,
           property = {
               "sling.servlet.paths=/bin/academy/weather",
               "sling.servlet.methods=GET"
           })
public class WeatherSearchServlet extends SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request,
                         SlingHttpServletResponse response)
            throws ServletException, IOException {

        response.setContentType("application/json;charset=UTF-8");
        response.setHeader("Cache-Control", "no-cache");

        String city    = request.getParameter("city");
        String country = request.getParameter("country");

        // ── Input validation — never trust the browser ─────────────────────
        if (city == null || city.isBlank()) {
            writeError(response, 400, "city parameter is required");
            return;
        }
        if (city.length() > 100) {
            writeError(response, 400, "city name too long");
            return;
        }

        // ── Geocode + fetch ────────────────────────────────────────────────
        // Reuse the package-private methods from WeatherModel —
        // they hold the API logic; this class is just the HTTP wiring.
        WeatherModel helper = new WeatherModel();
        try {
            double[] coords = helper.geocode(city, country);
            helper.fetchCurrentWeather(coords[0], coords[1]);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            writeError(response, 502, "Weather API call interrupted");
            return;
        } catch (Exception e) {
            writeError(response, 502, "Could not find weather for \u201c" + city + "\u201d");
            return;
        }

        // ── Build and write the JSON response ──────────────────────────────
        JsonObjectBuilder json = Json.createObjectBuilder()
            .add("location",            helper.getResolvedLocation())
            .add("temperature",         helper.getTemperature())
            .add("apparentTemperature", helper.getApparentTemperature())
            .add("windSpeed",           helper.getWindSpeed())
            .add("windDirection",       helper.getWindDirection())
            .add("humidity",            helper.getHumidity())
            .add("precipitation",       helper.getPrecipitation())
            .add("conditions",          helper.getConditions());

        response.getWriter().write(json.build().toString());
    }

    // ── Helper: write a JSON error response with the given HTTP status ─────
    private void writeError(SlingHttpServletResponse response, int status, String message)
            throws IOException {
        response.setStatus(status);
        response.getWriter().write(
            Json.createObjectBuilder().add("error", message).build().toString()
        );
    }
}
📖 Why this code?

The Servlet is thin — it validates input, delegates to the model's shared API methods, and formats the response. All business logic stays in WeatherModel.

  • "sling.servlet.paths=/bin/academy/weather" — path-based registration (module 10). Any GET to this URL routes here regardless of content. The /bin/ prefix is the AEM convention for non-content endpoints and is typically allowlisted through the Dispatcher.
  • response.setContentType("application/json;charset=UTF-8") — tells the browser this response is JSON, not HTML. Without this, some browsers try to render it or download it as a file. Always set it before writing to the response.
  • response.setHeader("Cache-Control", "no-cache") — weather data is time-sensitive. Without this, some browsers (and Dispatcher) cache the first response and serve it for subsequent searches, making the user see stale data. no-cache means "always revalidate with the server."
  • Server-side validation first — if (city == null || city.isBlank()) rejects missing inputs with HTTP 400 before calling any API. The browser's required attribute prevents most empty submissions, but a direct curl call bypasses it entirely. Always validate server-side.
  • Thread.currentThread().interrupt() — when an InterruptedException is caught, the interrupted flag must be re-set. Not doing this violates the Java threading contract and can cause subtle hangs in thread pools that check for interruption. The return immediately after prevents further processing on an interrupted thread.
  • writeError(response, 502, "...") — HTTP 502 (Bad Gateway) correctly signals that this AEM server couldn't reach the upstream weather API, distinguishing it from a 400 (bad client request) or a 500 (AEM bug). Correct status codes let monitoring systems distinguish user errors from infrastructure failures.

📖 Why this code?

The dialog now makes the city optional — authors can leave it empty and let visitors use the search form exclusively, or pre-fill it so the page always shows a default location on load.

  • required="{Boolean}true" has been removed — the component is now useful even without an author-configured city, since the interactive search form is always present.

Step 5 — Clientlib

/aem-academy/ui.apps/src/main/content/jcr_root/apps/academy/clientlibs/weather/.content.xml (academy.ui.apps)<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:jcr="http://www.jcp.org/jcr/1.0"

📖 Why this code?

All rules are scoped to .academy-weather — no global selectors leak into the rest of the page.

Step 7 — JavaScript

/apps/academy/clientlibs/weather/js/weather.js(function () {
  'use strict';

  /**
   * For each Weather component on the page:
   *   1. Listen for form submission.
   *   2. Call /bin/academy/weather?city=...&country=...
   *   3. Render the JSON response as a table in the dynamic results area.
   */
  document.querySelectorAll('[data-weather-widget]').forEach(function (widget) {
    var form     = widget.querySelector('[data-weather-form]');
    var cityIn   = widget.querySelector('[data-weather-city]');
    var countryIn= widget.querySelector('[data-weather-country]');
    var results  = widget.querySelector('[data-weather-results]');
    var btn      = form && form.querySelector('[data-weather-submit]');

    if (!form || !cityIn || !results) return;

    form.addEventListener('submit', function (e) {
      e.preventDefault();

      var city    = cityIn.value.trim();
      var country = countryIn ? countryIn.value.trim() : '';

      if (!city) {
        results.innerHTML = '<p class="academy-weather__error">Please enter a city name.</p>';
        cityIn.focus();
        return;
      }

      // ── Loading state ──────────────────────────────────────────────────
      results.innerHTML = '<p class="academy-weather__loading">Fetching weather for ' +
        escapeHtml(city) + '...</p>';
      if (btn) { btn.disabled = true; btn.textContent = 'Loading…'; }

      // ── Fetch from the Sling Servlet ───────────────────────────────────
      var url = '/bin/academy/weather?city=' + encodeURIComponent(city);
      if (country) url += '&country=' + encodeURIComponent(country);

      fetch(url, { credentials: 'same-origin' })
        .then(function (r) { return r.json(); })
        .then(function (data) {
          if (data.error) {
            results.innerHTML = '<p class="academy-weather__error">' +
              escapeHtml(data.error) + '</p>';
          } else {
            results.innerHTML = buildTable(data);
          }
        })
        .catch(function () {
          results.innerHTML = '<p class="academy-weather__error">' +
            'Request failed — check your network connection.</p>';
        })
        .finally(function () {
          if (btn) { btn.disabled = false; btn.textContent = 'Get Weather'; }
        });
    });
  });

  // ── Build a <table> from the servlet's JSON response ──────────────────
  function buildTable(data) {
    var rows = [
      ['Temperature',    data.temperature         + '\u00b0C'],
      ['Feels Like',     data.apparentTemperature  + '\u00b0C'],
      ['Conditions',     data.conditions],
      ['Wind Speed',     data.windSpeed            + ' km/h'],
      ['Wind Direction', compassLabel(data.windDirection)],
      ['Humidity',       data.humidity             + '%'],
      ['Precipitation',  data.precipitation        + ' mm'],
    ];

    var html  = '<table class="academy-weather__table">';
    html     += '<caption>' + escapeHtml(data.location) + '</caption>';
    html     += '<thead><tr><th scope="col">Metric</th><th scope="col">Value</th></tr></thead>';
    html     += '<tbody>';
    rows.forEach(function (row) {
      html += '<tr><td>' + row[0] + '</td><td>' + escapeHtml(String(row[1])) + '</td></tr>';
    });
    html += '</tbody></table>';
    return html;
  }

  // Convert degrees to a cardinal compass label — e.g. 247 → "247° (WSW)"
  function compassLabel(deg) {
    var dirs = ['N','NNE','NE','ENE','E','ESE','SE','SSE',
                'S','SSW','SW','WSW','W','WNW','NW','NNW'];
    return deg + '\u00b0 (' + dirs[Math.round(deg / 22.5) % 16] + ')';
  }

  // Prevent XSS when inserting API-returned strings into innerHTML
  function escapeHtml(str) {
    return String(str)
      .replace(/&/g, '&amp;')
      .replace(/</g,  '&lt;')
      .replace(/>/g,  '&gt;')
      .replace(/"/g,  '&quot;');
  }

}());
📖 Why this code?

The JavaScript is the bridge between the user's input and the Sling Servlet. It follows the same IIFE + data-attribute pattern used in the navigation component (module 28).

  • document.querySelectorAll('[data-weather-widget]') — selects all Weather component instances on the page. If an author places two Weather widgets on one page, each gets its own independent handler. Data attributes instead of class names keep the JavaScript decoupled from the CSS.
  • e.preventDefault() — stops the browser's default form submission (which would reload the page). All the handling happens in the fetch() call below it.
  • credentials: 'same-origin' — sends cookies with the request so AEM's authentication mechanism works. Without it, the Servlet receives an anonymous request, which AEM may reject on the author instance if the /bin/academy/weather path requires authentication.
  • escapeHtml() — critical for XSS prevention. The API returns city and country names from Open-Meteo, which could theoretically contain characters like < or ". Inserting API-returned data directly into innerHTML without escaping creates an injection vulnerability. This helper prevents it. HTL does this automatically; when writing raw JavaScript you must do it yourself.
  • .finally() — re-enables the submit button regardless of success or failure. Without it, a network error leaves the button permanently disabled and the user can't try again.
  • compassLabel(deg) — converts the raw degree number (0–360) to a human-readable compass direction. Math.round(deg / 22.5) % 16 maps any degree value to one of 16 compass points. % 16 handles the wrap-around from 360° back to 0° (North).

📖 Why this code?

The template now has three layers, each with a distinct purpose and visible only under specific conditions.

  • Search form (always visible) — the <form> is unconditional. Authors see it in preview (?wcmmode=disabled); end users see it on the publish instance. Both can type a city and click "Get Weather" without any pre-configuration.
  • novalidate on the form — disables the browser's native validation bubbles (which are un-styleable and accessibility-inconsistent). The JavaScript handles validation manually in if (!city) { ... }. This is the correct pattern when you want full control over validation UX.
  • Server-rendered table (data-sly-test="${weather.available}") — only appears when the author set a city in the dialog and the API call succeeded. This is the "instant load" experience — the page arrives pre-populated without waiting for a JavaScript fetch.
  • Dynamic results (data-weather-results) — an empty div. weather.js writes a table into it after a form submission. It sits below the server-rendered table, so if the author pre-configured Lisbon and the user searches for Tokyo, they see both results without one replacing the other.
  • data-weather-widget, data-weather-form, data-weather-city, data-weather-country, data-weather-submit, data-weather-results — every JavaScript hook is a data- attribute, not a CSS class. This keeps styling and behaviour concerns cleanly separated: changing a BEM class in CSS never accidentally breaks a JavaScript selector.
