Custom Components Workshop

Two complete components, built from an empty starting point: an extended Image component that reads and displays a DAM asset's metadata, and a Weather component that geocodes an author-entered city and pulls live conditions from a free public API.

What you'll learn

  • Exactly where in an AEM project's Maven structure new Java, component, and dialog files belong
  • Extending a Core Component by resource type inheritance instead of building from scratch
  • Reading DAM asset metadata from a Sling Model
  • Calling an external REST API from a Sling Model, and why that's a pattern to use carefully

Before you start: where this code lives

This uses the exact /aem-academy project structure from module 00's "Before you start" — go back there for the full picture if you skipped it. As a reminder: Java goes in core (academy.core), anything an author drags onto a page goes in ui.apps (academy.ui.apps), and every path below is given in full from /aem-academy, the project root.

Mental model Running mvn clean install -PautoInstallSinglePackage from /aem-academy builds every module and deploys the whole thing to localhost:4502 in one command. You won't run javac or copy files into the repository by hand at any point.

Both components below assume your project already depends on the AEM Core Components (the project archetype includes this by default as core.wcm.components.core). If a Core Components class doesn't resolve when you build, add that dependency to /aem-academy/core/pom.xml (academy.core) before continuing.

Component 1 — Image with Metadata

Rather than building an image component from scratch, we extend the Core Components Image component the same way module 3 described overlays working: by pointing resourceSuperType at it. We get the existing image-picking dialog, accessibility markup, and responsive image handling for free, and add one thing on top — a small metadata panel read from the underlying DAM asset.

Step 1 — the Java Sling Model

Save this as a brand new file at:

/aem-academy/core/src/main/java/biz/netcentric/academy/components/imagemetadata/ImageMetadataModel.java (academy.core)package biz.netcentric.academy.components.imagemetadata;

import com.adobe.cq.wcm.core.components.models.Image;
import com.day.cq.dam.api.Asset;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.api.resource.ResourceResolver;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.Self;
import org.apache.sling.models.annotations.injectorspecific.SlingObject;
import org.apache.sling.models.annotations.via.ResourceSuperType;

import javax.annotation.PostConstruct;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/imagemetadata",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class ImageMetadataModel {

    @Self
    @org.apache.sling.models.annotations.via.Via(type = ResourceSuperType.class)
    private Image coreImage;

    @SlingObject
    private ResourceResolver resourceResolver;

    private String width;
    private String height;
    private String format;
    private String cameraModel;

    @PostConstruct
    protected void init() {
        if (coreImage == null || coreImage.getFileReference() == null) {
            return;
        }
        Resource assetResource = resourceResolver.getResource(coreImage.getFileReference());
        Asset asset = assetResource != null ? assetResource.adaptTo(Asset.class) : null;
        if (asset == null) {
            return;
        }
        width = asset.getMetadataValue("tiff:ImageWidth");
        height = asset.getMetadataValue("tiff:ImageLength");
        format = asset.getMetadataValue("dc:format");
        cameraModel = asset.getMetadataValue("tiff:Model");
    }

    public String getSrc() {
        return coreImage != null ? coreImage.getSrc() : null;
    }

    public String getAlt() {
        return coreImage != null ? coreImage.getAlt() : null;
    }

    public String getWidth() {
        return width;
    }

    public String getHeight() {
        return height;
    }

    public String getFormat() {
        return format;
    }

    public String getCameraModel() {
        return cameraModel;
    }

    public boolean hasMetadata() {
        return width != null || format != null;
    }
}
📖 Why this code?

This model demonstrates extending a Core Component and using the AEM Asset API to read metadata from DAM assets.

  • implements Image — the Core Components Image interface. By implementing this interface, the model can be used anywhere a Core Image model is expected, and inherits the interface contract for properties like getSrc() and getAlt().
  • @Via(type = ResourceSuperType.class) — injects the Core Components' own Image model for this resource, giving you src, alt, and link resolution without reimplementing them.
  • asset.getMetadataValue("tiff:ImageWidth") — reads standard EXIF/TIFF metadata from the DAM asset. The tiff: namespace prefix is standard EXIF nomenclature — tiff:ImageWidth, tiff:ImageLength, tiff:Model (camera model) are common fields.

@Self @Via(type = ResourceSuperType.class) is the key line: it adapts the same resource to the core Image component's own model first, then hands you that fully-built object to read from — rather than re-implementing image rendering yourself. Module 8 already covered this composition pattern in depth; this is it in practice.

📖 Why this code?

The component definition for ImageMetadata — the XML that registers it as a component and declares it inherits from Core Image.

  • sling:resourceSuperType="core/wcm/components/image/v3/image" — this line is why the component has a dialog without any _cq_dialog folder of its own. 📖 Why this code?

The HTL template for the ImageMetadata component — notice how thin it is, because all logic lives in the model.

  • data-sly-use.metadata="...ImageMetadataModel" — adapts the resource to the model. All image src/alt resolution and all metadata reading happens inside the model's @PostConstruct.
  • data-sly-test="${metadata.hasMetadata}" — the entire metadata block is absent from the HTML if the asset has no EXIF data (e.g. a manually cropped screenshot). The template makes zero decisions about when this is or isn't relevant — that logic is in hasMetadata().
Mental model There's no _cq_dialog folder in this component at all — and that's deliberate. Since we didn't provide one, Sling's resourceType resolution from module 3 walks up to resourceSuperType and uses the core Image component's own dialog instead. The image-picking UI an author sees is the exact same one the standard Image component uses.

Component 2 — Weather

An author enters a city (and optionally a country, to disambiguate places that share a name), the component geocodes it through Open-Meteo's free geocoding API, then fetches current conditions from Open-Meteo's forecast API for those coordinates. No API key is required for either endpoint.

Step 1 — the Java Sling Model

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherModel.java (academy.core)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import javax.annotation.PostConstruct;
import javax.json.Json;
import javax.json.JsonArray;
import javax.json.JsonObject;
import java.io.IOException;
import java.io.StringReader;
import java.net.URI;
import java.net.URLEncoder;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/weather",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class WeatherModel {

    private static final Logger LOG = LoggerFactory.getLogger(WeatherModel.class);
    private static final HttpClient HTTP_CLIENT = HttpClient.newHttpClient();

    @ValueMapValue
    private String city;

    @ValueMapValue
    private String country;

    private String resolvedLocation;
    private Double temperature;
    private Double windspeed;
    private String error;

    @PostConstruct
    protected void init() {
        if (city == null || city.isBlank()) {
            return;
        }
        try {
            double[] coords = geocode(city, country);
            fetchCurrentWeather(coords[0], coords[1]);
        } catch (Exception e) {
            LOG.warn("Weather lookup failed for city={}, country={}", city, country, e);
            error = "Could not load weather for this location.";
        }
    }

    private double[] geocode(String city, String country) throws IOException, InterruptedException {
        String query = URLEncoder.encode(city, StandardCharsets.UTF_8);
        String url = "https://geocoding-api.open-meteo.com/v1/search?name=" + query + "&count=10";
        JsonObject body = fetchJson(url);
        JsonArray results = body.getJsonArray("results");
        if (results == null || results.isEmpty()) {
            throw new IOException("No geocoding results for " + city);
        }

        JsonObject match = results.getJsonObject(0);
        if (country != null && !country.isBlank()) {
            for (int i = 0; i < results.size(); i++) {
                JsonObject candidate = results.getJsonObject(i);
                if (country.equalsIgnoreCase(candidate.getString("country", ""))) {
                    match = candidate;
                    break;
                }
            }
        }

        resolvedLocation = match.getString("name") + ", " + match.getString("country", "");
        return new double[]{
                match.getJsonNumber("latitude").doubleValue(),
                match.getJsonNumber("longitude").doubleValue()
        };
    }

    private void fetchCurrentWeather(double latitude, double longitude) throws IOException, InterruptedException {
        String url = String.format(
                "https://api.open-meteo.com/v1/forecast?latitude=%s&longitude=%s&current_weather=true",
                latitude, longitude);
        JsonObject body = fetchJson(url);
        JsonObject current = body.getJsonObject("current_weather");
        temperature = current.getJsonNumber("temperature").doubleValue();
        windspeed   = current.getJsonNumber("windspeed").doubleValue();
    }

    private JsonObject fetchJson(String url) throws IOException, InterruptedException {
        HttpRequest request = HttpRequest.newBuilder(URI.create(url)).GET().build();
        HttpResponse<String> response = HTTP_CLIENT.send(request, HttpResponse.BodyHandlers.ofString());
        return Json.createReader(new StringReader(response.body())).readObject();
    }

    public String  getCity()             { return city; }
    public String  getResolvedLocation() { return resolvedLocation; }
    public Double  getTemperature()      { return temperature; }
    public Double  getWindspeed()        { return windspeed; }
    public String  getError()            { return error; }
    public boolean isAvailable()         { return temperature != null; }
}
📖 Why this code?

WeatherModel demonstrates a real-world model that calls an external API — deliberately showing the right structure alongside a pattern to avoid.

  • @ValueMapValue private String city and private String country — the author's input from the dialog. These are the only things the model reads from the repository.
  • @PostConstruct protected void init() — this is where the HTTP calls happen in the educational example. The comment in the module explicitly flags this as a pattern to understand and then improve with Sling Jobs (module 18).
  • The separate geocode() and fetchCurrentWeather() private methods keep the init() method short and each concern independently readable.
Common pitfall Making a synchronous outbound HTTP call inside a Sling Model means every single page render waits on a third-party API — slow, fragile if that API has an outage, and an easy way to get rate-limited. This is fine for a training exercise; module 18 (Sling Jobs) shows the production-correct version: a scheduled background job fetches and caches the weather periodically, and the model just reads the cached value.

📖 Why this code?

The Weather component's dialog — two simple textfields, one required (city) and one optional (country).

  • Both fields use name="./city" and name="./country" — the ./ prefix writes values to the component's own content node. These are the exact property names @ValueMapValue private String city reads in the model.
  • The dialog has no required attribute on the country field — an empty string is a valid value, and the model handles disambiguation when country is absent.

Step 3 — the render script

/aem-academy/ui.apps/src/main/content/jcr_root/apps/academy/components/weather/weather.html (academy.ui.apps)<div data-sly-use.weather="biz.netcentric.academy.components.weather.WeatherModel" class="academy-weather">

📖 Why this code?

The Weather component's render template — again deliberately thin, reflecting the principle that templates only do layout.

  • data-sly-test="${weather.error}" renders the error block when getError() returns a non-empty string — handling API failures gracefully rather than crashing silently.
  • data-sly-test="${weather.available}" gates the full weather display on the model having successfully fetched data. This means partially failed states (city found, weather fetch failed) don't render broken HTML.

Component 2 (Extended) — Interactive Weather Search

The original Weather component works, but it has one friction point: the only way to look up a city is through the author dialog. This extension adds a live search form directly on the rendered page — any visitor (and the author in preview mode) can type a city name, click a button, and see the full weather data appear in a table below, without a page reload. It keeps the original component's server-rendered output for the author-configured city and layers the interactive search on top of it.

This section introduces two new patterns: a path-based Sling Servlet (the AJAX endpoint the browser calls) and a clientlib containing all the CSS and JavaScript the form needs. The WeatherModel is also updated to expose more data fields and to share its API methods with the Servlet.

What changes, what doesn't The component resource type (academy/components/weather) stays the same — this is an enhancement of the existing component, not a new one. The Sling Model gains new fields. A new Servlet class is added to the same Java package. A new clientlib provides CSS + JS. The dialog becomes optional. The HTL template gains a search form and a dynamic results container.

Step 1 — Update WeatherModel to expose more fields and share API methods

The model gains five new weather fields, a WMO weather-code lookup map, and changes its API call to the newer current= parameter format. Key methods are also promoted to package visibility so the Servlet can reuse them without duplicating code.

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherModel.java (academy.core — replace the original)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import javax.annotation.PostConstruct;
import javax.json.Json;
import javax.json.JsonArray;
import javax.json.JsonObject;
import java.io.IOException;
import java.io.StringReader;
import java.net.URI;
import java.net.URLEncoder;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.util.Map;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/weather",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class WeatherModel {

    private static final Logger LOG = LoggerFactory.getLogger(WeatherModel.class);

    // Package-visible so WeatherSearchServlet can reuse the same HTTP client
    static final HttpClient HTTP_CLIENT = HttpClient.newHttpClient();

    // WMO weather interpretation codes → human-readable label
    // Full reference: https://open-meteo.com/en/docs#weathervariables
    static final Map<Integer, String> WMO_CODES = Map.ofEntries(
        Map.entry(0,  "Clear sky"),
        Map.entry(1,  "Mainly clear"), Map.entry(2, "Partly cloudy"), Map.entry(3, "Overcast"),
        Map.entry(45, "Foggy"),        Map.entry(48, "Depositing rime fog"),
        Map.entry(51, "Light drizzle"),Map.entry(53, "Moderate drizzle"),Map.entry(55, "Dense drizzle"),
        Map.entry(61, "Slight rain"),  Map.entry(63, "Moderate rain"), Map.entry(65, "Heavy rain"),
        Map.entry(71, "Slight snow"),  Map.entry(73, "Moderate snow"), Map.entry(75, "Heavy snow"),
        Map.entry(80, "Slight showers"),Map.entry(81,"Moderate showers"),Map.entry(82,"Violent showers"),
        Map.entry(95, "Thunderstorm"),
        Map.entry(96, "Thunderstorm with hail"), Map.entry(99, "Heavy thunderstorm with hail")
    );

    @ValueMapValue private String city;
    @ValueMapValue private String country;

    // Original fields
    private String resolvedLocation;
    private Double temperature;
    private String error;

    // Extended fields — new in this version
    private Double  apparentTemperature;
    private Double  windSpeed;
    private Integer windDirection;
    private Integer humidity;
    private Double  precipitation;
    private Integer weatherCode;
    private String  conditions;

    @PostConstruct
    protected void init() {
        if (city == null || city.isBlank()) return;
        try {
            double[] coords = geocode(city, country);
            fetchCurrentWeather(coords[0], coords[1]);
        } catch (Exception e) {
            LOG.warn("Weather lookup failed for city={}, country={}", city, country, e);
            error = "Could not load weather for \u201c" + city + "\u201d.";
        }
    }

    // Package-visible — reused by WeatherSearchServlet
    double[] geocode(String cityName, String countryName) throws IOException, InterruptedException {
        String query = URLEncoder.encode(cityName, StandardCharsets.UTF_8);
        String url   = "https://geocoding-api.open-meteo.com/v1/search?name=" + query + "&count=10";
        JsonObject body    = fetchJson(url);
        JsonArray  results = body.getJsonArray("results");
        if (results == null || results.isEmpty()) {
            throw new IOException("No geocoding results for \"" + cityName + "\"");
        }

        JsonObject match = results.getJsonObject(0);
        if (countryName != null && !countryName.isBlank()) {
            for (int i = 0; i < results.size(); i++) {
                JsonObject candidate = results.getJsonObject(i);
                if (countryName.equalsIgnoreCase(candidate.getString("country", ""))) {
                    match = candidate; break;
                }
            }
        }

        resolvedLocation = match.getString("name") + ", " + match.getString("country", "");
        return new double[]{
            match.getJsonNumber("latitude").doubleValue(),
            match.getJsonNumber("longitude").doubleValue()
        };
    }

    // Package-visible — reused by WeatherSearchServlet
    // Now uses the newer Open-Meteo current= format for more fields
    void fetchCurrentWeather(double lat, double lon) throws IOException, InterruptedException {
        String url = String.format(
            "https://api.open-meteo.com/v1/forecast" +
            "?latitude=%s&longitude=%s" +
            "&current=temperature_2m,apparent_temperature,wind_speed_10m," +
            "wind_direction_10m,relative_humidity_2m,weather_code,precipitation",
            lat, lon);

        JsonObject body    = fetchJson(url);
        JsonObject current = body.getJsonObject("current");

        temperature         = current.getJsonNumber("temperature_2m").doubleValue();
        apparentTemperature = current.getJsonNumber("apparent_temperature").doubleValue();
        windSpeed           = current.getJsonNumber("wind_speed_10m").doubleValue();
        windDirection       = current.getInt("wind_direction_10m");
        humidity            = current.getInt("relative_humidity_2m");
        weatherCode         = current.getInt("weather_code");
        precipitation       = current.getJsonNumber("precipitation").doubleValue();
        conditions          = WMO_CODES.getOrDefault(weatherCode, "Code " + weatherCode);
    }

    // Package-visible — reused by WeatherSearchServlet
    static JsonObject fetchJson(String url) throws IOException, InterruptedException {
        HttpRequest req  = HttpRequest.newBuilder(URI.create(url)).GET().build();
        HttpResponse<String> resp = HTTP_CLIENT.send(req, HttpResponse.BodyHandlers.ofString());
        return Json.createReader(new StringReader(resp.body())).readObject();
    }

    // ── Getters (original) ────────────────────────────────────────────────
    public String  getCity()             { return city; }
    public String  getResolvedLocation() { return resolvedLocation; }
    public Double  getTemperature()      { return temperature; }
    public String  getError()            { return error; }
    public boolean isAvailable()         { return temperature != null; }

    // ── Getters (extended) ────────────────────────────────────────────────
    public Double  getApparentTemperature() { return apparentTemperature; }
    public Double  getWindSpeed()           { return windSpeed; }
    public Integer getWindDirection()       { return windDirection; }
    public Integer getHumidity()            { return humidity; }
    public Double  getPrecipitation()       { return precipitation; }
    public String  getConditions()          { return conditions; }
}
📖 Why this code?

Three structural changes make the Servlet possible without duplicating any API code.

  • static final HttpClient HTTP_CLIENT (was private, now package-visible) — the Servlet needs an HTTP client. Reusing this one avoids creating a second idle connection pool. static means it's shared across all model instances and the Servlet; HttpClient is thread-safe so this is fine.
  • static final Map<Integer, String> WMO_CODES — WMO (World Meteorological Organisation) numeric codes for weather interpretation. Using Map.ofEntries() instead of Map.of() because Map.of() has a hard limit of 10 entries. The map is static (one instance shared by all) and final (immutable after creation).
  • geocode(), fetchCurrentWeather(), fetchJson() changed from private to package-visible (no modifier) — the Servlet lives in the same Java package (biz.netcentric.academy.components.weather) so it can call these methods directly. Keeping them out of the public API means they don't appear in any public interface or Javadoc.
  • current=temperature_2m,apparent_temperature,... — the newer Open-Meteo API parameter. The response now has a "current" object (not "current_weather") with underscore-suffixed field names. This format supports far more variables than the legacy endpoint.

Step 2 — Add WeatherSearchServlet

A path-based Sling Servlet that the browser calls via fetch(). It validates the input, delegates to the shared model methods, and returns JSON. This is the module 10 pattern applied to an interactive use case.

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherSearchServlet.java (academy.core — new file)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.servlets.SlingSafeMethodsServlet;
import org.osgi.service.component.annotations.Component;

import javax.json.Json;
import javax.json.JsonObjectBuilder;
import javax.servlet.Servlet;
import javax.servlet.ServletException;
import java.io.IOException;

/**
 * AJAX weather lookup endpoint.
 * GET /bin/academy/weather?city=London&country=UK
 * Returns JSON on success:  { "location": "...", "temperature": 15.2, ... }
 * Returns JSON on failure:  { "error": "City not found" }
 */
@Component(service = Servlet.class,
           property = {
               "sling.servlet.paths=/bin/academy/weather",
               "sling.servlet.methods=GET"
           })
public class WeatherSearchServlet extends SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request,
                         SlingHttpServletResponse response)
            throws ServletException, IOException {

        response.setContentType("application/json;charset=UTF-8");
        response.setHeader("Cache-Control", "no-cache");

        String city    = request.getParameter("city");
        String country = request.getParameter("country");

        // ── Server-side validation — never rely on the browser alone ──────
        if (city == null || city.isBlank()) {
            writeError(response, 400, "city parameter is required");
            return;
        }
        if (city.length() > 100) {
            writeError(response, 400, "city name too long");
            return;
        }

        // ── Reuse WeatherModel's package-visible API methods ───────────────
        WeatherModel helper = new WeatherModel();
        try {
            double[] coords = helper.geocode(city, country);
            helper.fetchCurrentWeather(coords[0], coords[1]);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();   // restore interrupted flag
            writeError(response, 502, "Weather API call interrupted");
            return;
        } catch (Exception e) {
            writeError(response, 502, "Could not find weather for \u201c" + city + "\u201d");
            return;
        }

        // ── Build the JSON response ────────────────────────────────────────
        JsonObjectBuilder json = Json.createObjectBuilder()
            .add("location",            helper.getResolvedLocation())
            .add("temperature",         helper.getTemperature())
            .add("apparentTemperature", helper.getApparentTemperature())
            .add("windSpeed",           helper.getWindSpeed())
            .add("windDirection",       helper.getWindDirection())
            .add("humidity",            helper.getHumidity())
            .add("precipitation",       helper.getPrecipitation())
            .add("conditions",          helper.getConditions());

        response.getWriter().write(json.build().toString());
    }

    private void writeError(SlingHttpServletResponse response, int status, String message)
            throws IOException {
        response.setStatus(status);
        response.getWriter().write(
            Json.createObjectBuilder().add("error", message).build().toString()
        );
    }
}
📖 Why this code?

The Servlet is intentionally thin — validate input, delegate to the model's shared methods, format the JSON. All business logic stays in WeatherModel.

  • "sling.servlet.paths=/bin/academy/weather" — path-based registration from module 10. Any GET to this URL routes here, regardless of what content node exists at that path. The /bin/ prefix is the AEM convention for non-content endpoints — Dispatcher allow-lists it separately from /content paths.
  • response.setContentType("application/json;charset=UTF-8") — tells the browser the response is JSON. Without this, some browsers try to render it as HTML or offer it as a file download.
  • response.setHeader("Cache-Control", "no-cache") — weather data is time-sensitive. Without this the Dispatcher (or browser) may cache the first result and serve it for all subsequent city lookups until the cache expires, making every search return London's weather.
  • Thread.currentThread().interrupt() after catching InterruptedException — restores the thread's interrupted flag. Not doing this violates the Java concurrency contract and can cause hangs in thread pools that check for interruption as their shutdown mechanism.
  • HTTP 400 for bad input, HTTP 502 for upstream API failure — these status codes let monitoring systems tell apart "user sent bad data" from "the Open-Meteo API is unreachable." Returning 200 with an error message in the body makes both look identical to a load balancer or APM tool.

Step 6 — JavaScript

/apps/academy/clientlibs/weather/js/weather.js(function () {
  'use strict';

  /**
   * For each Weather component on the page:
   *   1. Intercept form submission.
   *   2. Call GET /bin/academy/weather?city=...&country=...
   *   3. Render the JSON response as a table.
   */
  document.querySelectorAll('[data-weather-widget]').forEach(function (widget) {
    var form      = widget.querySelector('[data-weather-form]');
    var cityIn    = widget.querySelector('[data-weather-city]');
    var countryIn = widget.querySelector('[data-weather-country]');
    var results   = widget.querySelector('[data-weather-results]');
    var btn       = form && form.querySelector('[data-weather-submit]');

    if (!form || !cityIn || !results) return;

    form.addEventListener('submit', function (e) {
      e.preventDefault();

      var city    = cityIn.value.trim();
      var country = countryIn ? countryIn.value.trim() : '';

      if (!city) {
        results.innerHTML = '<p class="academy-weather__error">Please enter a city name.</p>';
        cityIn.focus();
        return;
      }

      // ── Show loading state ─────────────────────────────────────────────
      results.innerHTML = '<p class="academy-weather__loading">Fetching weather for '
                        + escapeHtml(city) + '…</p>';
      if (btn) { btn.disabled = true; btn.textContent = 'Loading…'; }

      // ── Call the Sling Servlet ─────────────────────────────────────────
      var url = '/bin/academy/weather?city=' + encodeURIComponent(city);
      if (country) url += '&country=' + encodeURIComponent(country);

      fetch(url, { credentials: 'same-origin' })
        .then(function (r)    { return r.json(); })
        .then(function (data) {
          results.innerHTML = data.error
            ? '<p class="academy-weather__error">' + escapeHtml(data.error) + '</p>'
            : buildTable(data);
        })
        .catch(function () {
          results.innerHTML = '<p class="academy-weather__error">'
                            + 'Request failed — check your network connection.</p>';
        })
        .finally(function () {
          if (btn) { btn.disabled = false; btn.textContent = 'Get Weather'; }
        });
    });
  });

  // ── Build a <table> from the JSON the Servlet returns ──────────────────
  function buildTable(data) {
    var rows = [
      ['Temperature',    data.temperature         + '\u00b0C'],
      ['Feels Like',     data.apparentTemperature  + '\u00b0C'],
      ['Conditions',     data.conditions],
      ['Wind Speed',     data.windSpeed            + ' km/h'],
      ['Wind Direction', compassLabel(data.windDirection)],
      ['Humidity',       data.humidity             + '%'],
      ['Precipitation',  data.precipitation        + ' mm'],
    ];
    var html = '<table class="academy-weather__table">';
    html += '<caption>' + escapeHtml(data.location) + '</caption>';
    html += '<thead><tr><th scope="col">Metric</th><th scope="col">Value</th></tr></thead>';
    html += '<tbody>';
    rows.forEach(function (row) {
      html += '<tr><td>' + row[0] + '</td><td>' + escapeHtml(String(row[1])) + '</td></tr>';
    });
    return html + '</tbody></table>';
  }

  // Convert 0-360° to a cardinal compass label — e.g. 247 → "247° (WSW)"
  function compassLabel(deg) {
    var dirs = ['N','NNE','NE','ENE','E','ESE','SE','SSE',
                'S','SSW','SW','WSW','W','WNW','NW','NNW'];
    return deg + '\u00b0 (' + dirs[Math.round(deg / 22.5) % 16] + ')';
  }

  // Prevent XSS when injecting API-returned strings into innerHTML
  function escapeHtml(str) {
    return String(str)
      .replace(/&/g, '&amp;').replace(/</g, '&lt;')
      .replace(/>/g, '&gt;').replace(/"/g, '&quot;');
  }

}());
📖 Why this code?

The JavaScript follows the IIFE + data-attribute pattern from the module 28 navigation component — no framework, no global variables, works with multiple component instances on one page.

  • document.querySelectorAll('[data-weather-widget]') — selecting by data attribute, not by CSS class, means you can restyle the component (rename BEM classes) without breaking the JavaScript. All five data-weather-* attributes serve exclusively as JS hooks.
  • e.preventDefault() — stops the browser's default form submit (which would reload the page with the form data as query parameters). The fetch call below handles the request instead.
  • credentials: 'same-origin' — sends the browser's session cookie with the request. Without it, AEM author instance can reject the request as anonymous (depending on how /bin/academy/weather is configured in the dispatcher/auth settings).
  • escapeHtml() — the critical XSS guard. Open-Meteo returns city names from their database; a pathological city name containing <script> (however unlikely) would execute if inserted directly into innerHTML without escaping. This function neutralises it. HTL escapes automatically; raw JavaScript DOM manipulation does not.
  • .finally() — re-enables the button whether the request succeeded, failed, or was rejected by the servlet. Without this, a single failed request permanently disables the button until the user reloads the page.
  • compassLabel(deg) — Math.round(deg / 22.5) % 16 converts any 0–360° bearing to one of 16 compass points. The % 16 handles the wrap-around: 360° → index 16 → index 0 → "N", the same as 0°.

📖 Why this code?

Three independent layers co-exist in the same template, each conditional on different state.

  • Search form — unconditional. No data-sly-test. Present on every render for every user. Both the author in preview (?wcmmode=disabled) and the end user on publish can type a city and click the button.
