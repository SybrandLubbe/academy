Custom Components Workshop

Two complete components, built from an empty starting point: an extended Image component that reads and displays a DAM asset's metadata, and a Weather component that geocodes an author-entered city and pulls live conditions from a free public API.

What you'll learn

  • Exactly where in an AEM project's Maven structure new Java, component, and dialog files belong
  • Extending a Core Component by resource type inheritance instead of building from scratch
  • Reading DAM asset metadata from a Sling Model
  • Calling an external REST API from a Sling Model, and why that's a pattern to use carefully

Before you start: where this code lives

This uses the exact /aem-academy project structure from module 00's "Before you start" — go back there for the full picture if you skipped it. As a reminder: Java goes in core (academy.core), anything an author drags onto a page goes in ui.apps (academy.ui.apps), and every path below is given in full from /aem-academy, the project root.

Mental model Running mvn clean install -PautoInstallSinglePackage from /aem-academy builds every module and deploys the whole thing to localhost:4502 in one command. You won't run javac or copy files into the repository by hand at any point.

Both components below assume your project already depends on the AEM Core Components (the project archetype includes this by default as core.wcm.components.core). If a Core Components class doesn't resolve when you build, add that dependency to /aem-academy/core/pom.xml (academy.core) before continuing.

Component 1 — Image with Metadata

Rather than building an image component from scratch, we extend the Core Components Image component the same way module 3 described overlays working: by pointing resourceSuperType at it. We get the existing image-picking dialog, accessibility markup, and responsive image handling for free, and add one thing on top — a small metadata panel read from the underlying DAM asset.

Step 1 — the Java Sling Model

Save this as a brand new file at:

/aem-academy/core/src/main/java/biz/netcentric/academy/components/imagemetadata/ImageMetadataModel.java (academy.core)package biz.netcentric.academy.components.imagemetadata;

import com.adobe.cq.wcm.core.components.models.Image;
import com.day.cq.dam.api.Asset;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.api.resource.ResourceResolver;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.Self;
import org.apache.sling.models.annotations.injectorspecific.SlingObject;
import org.apache.sling.models.annotations.via.ResourceSuperType;

import javax.annotation.PostConstruct;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/imagemetadata",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class ImageMetadataModel {

    @Self
    @org.apache.sling.models.annotations.via.Via(type = ResourceSuperType.class)
    private Image coreImage;

    @SlingObject
    private ResourceResolver resourceResolver;

    private String width;
    private String height;
    private String format;
    private String cameraModel;

    @PostConstruct
    protected void init() {
        if (coreImage == null || coreImage.getFileReference() == null) {
            return;
        }
        Resource assetResource = resourceResolver.getResource(coreImage.getFileReference());
        Asset asset = assetResource != null ? assetResource.adaptTo(Asset.class) : null;
        if (asset == null) {
            return;
        }
        width = asset.getMetadataValue("tiff:ImageWidth");
        height = asset.getMetadataValue("tiff:ImageLength");
        format = asset.getMetadataValue("dc:format");
        cameraModel = asset.getMetadataValue("tiff:Model");
    }

    public String getSrc() {
        return coreImage != null ? coreImage.getSrc() : null;
    }

    public String getAlt() {
        return coreImage != null ? coreImage.getAlt() : null;
    }

    public String getWidth() {
        return width;
    }

    public String getHeight() {
        return height;
    }

    public String getFormat() {
        return format;
    }

    public String getCameraModel() {
        return cameraModel;
    }

    public boolean hasMetadata() {
        return width != null || format != null;
    }
}

@Self @Via(type = ResourceSuperType.class) is the key line: it adapts the same resource to the core Image component's own model first, then hands you that fully-built object to read from — rather than re-implementing image rendering yourself. Module 8 already covered this composition pattern in depth; this is it in practice.

Mental model There's no _cq_dialog folder in this component at all — and that's deliberate. Since we didn't provide one, Sling's resourceType resolution from module 3 walks up to resourceSuperType and uses the core Image component's own dialog instead. The image-picking UI an author sees is the exact same one the standard Image component uses.

Step 4 — build, deploy, and activate it

terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

Module 11 covered the full activation flow in detail — Template Editor → the layout container's Policy → allow the Academy Training component group — go back there if you need the step-by-step version. The one thing worth calling out specifically here: even though this component inherits its dialog from the core Image component, it does not inherit being allowed. academy/components/imagemetadata is its own distinct resource type with its own entry in the policy's component list, separate from the standard Image component — allow it explicitly, the same as any other new component.

Once it's allowed and deployed, open any page in the AEM editor, drag the new Image with Metadata component from the component browser (it sits in the "Academy Training" group) into a paragraph system, and pick any asset from /content/dam the same way you would with a normal Image component. If the asset has EXIF/TIFF metadata (most camera photos do; a plain screenshot usually won't), the dimensions, format, and camera model appear underneath it.

Try it with students Upload two assets to /content/dam/academy — one photo straight from a phone camera, one plain screenshot or graphic — and place both on a page with this component. Compare what renders for each, and ask students to predict which metadata fields will be empty before they look.

Component 2 — Weather

An author enters a city (and optionally a country, to disambiguate places that share a name), the component geocodes it through Open-Meteo's free geocoding API, then fetches current conditions from Open-Meteo's forecast API for those coordinates. No API key is required for either endpoint.

Step 1 — the Java Sling Model

/aem-academy/core/src/main/java/biz/netcentric/academy/components/weather/WeatherModel.java (academy.core)package biz.netcentric.academy.components.weather;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import javax.annotation.PostConstruct;
import javax.json.Json;
import javax.json.JsonArray;
import javax.json.JsonObject;
import java.io.IOException;
import java.io.StringReader;
import java.net.URI;
import java.net.URLEncoder;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/weather",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
public class WeatherModel {

    private static final Logger LOG = LoggerFactory.getLogger(WeatherModel.class);
    private static final HttpClient HTTP_CLIENT = HttpClient.newHttpClient();

    @ValueMapValue
    private String city;

    @ValueMapValue
    private String country;

    private String resolvedLocation;
    private Double temperature;
    private Double windspeed;
    private String error;

    @PostConstruct
    protected void init() {
        if (city == null || city.isBlank()) {
            return;
        }
        try {
            double[] coords = geocode(city, country);
            fetchCurrentWeather(coords[0], coords[1]);
        } catch (Exception e) {
            LOG.warn("Weather lookup failed for city={}, country={}", city, country, e);
            error = "Could not load weather for this location.";
        }
    }

    private double[] geocode(String city, String country) throws IOException, InterruptedException {
        String query = URLEncoder.encode(city, StandardCharsets.UTF_8);
        String url = "https://geocoding-api.open-meteo.com/v1/search?name=" + query + "&count=10";
        JsonObject body = fetchJson(url);
        JsonArray results = body.getJsonArray("results");
        if (results == null || results.isEmpty()) {
            throw new IOException("No geocoding results for " + city);
        }

        JsonObject match = results.getJsonObject(0);
        if (country != null && !country.isBlank()) {
            for (int i = 0; i < results.size(); i++) {
                JsonObject candidate = results.getJsonObject(i);
                if (country.equalsIgnoreCase(candidate.getString("country", ""))) {
                    match = candidate;
                    break;
                }
            }
        }

        resolvedLocation = match.getString("name") + ", " + match.getString("country", "");
        return new double[]{
                match.getJsonNumber("latitude").doubleValue(),
                match.getJsonNumber("longitude").doubleValue()
        };
    }

    private void fetchCurrentWeather(double latitude, double longitude) throws IOException, InterruptedException {
        String url = String.format(
                "https://api.open-meteo.com/v1/forecast?latitude=%s&longitude=%s¤t_weather=true",
                latitude, longitude);
        JsonObject body = fetchJson(url);
        JsonObject current = body.getJsonObject("current_weather");
        temperature = current.getJsonNumber("temperature").doubleValue();
        windspeed = current.getJsonNumber("windspeed").doubleValue();
    }

    private JsonObject fetchJson(String url) throws IOException, InterruptedException {
        HttpRequest request = HttpRequest.newBuilder(URI.create(url)).GET().build();
        HttpResponse<String> response = HTTP_CLIENT.send(request, HttpResponse.BodyHandlers.ofString());
        return Json.createReader(new StringReader(response.body())).readObject();
    }

    public String getCity() {
        return city;
    }

    public String getResolvedLocation() {
        return resolvedLocation;
    }

    public Double getTemperature() {
        return temperature;
    }

    public Double getWindspeed() {
        return windspeed;
    }

    public String getError() {
        return error;
    }

    public boolean isAvailable() {
        return temperature != null;
    }
}
Common pitfall Making a synchronous outbound HTTP call inside a Sling Model means every single page render waits on a third-party API — slow, fragile if that API has an outage, and an easy way to get rate-limited. This is fine for a training exercise; module 18 (Sling Jobs) shows the production-correct version: a scheduled background job fetches and caches the weather periodically, and the model just reads the cached value.

Knowledge Check

Ten questions to ask students once they've finished this module — answers are hidden by default so you can quiz live before revealing them.

  1. What single declaration makes ImageMetadataModel reuse the core Image component's dialog, instead of needing its own _cq_dialog?

    Show answer

    Setting sling:resourceSuperType="core/wcm/components/image/v3/image" on the component definition — with no _cq_dialog folder of its own, resolution falls back to the parent's dialog.

  2. Which Asset API method does ImageMetadataModel call to read DAM metadata like image width?

    Show answer

    asset.getMetadataValue("tiff:ImageWidth") (and similarly for tiff:ImageLength, dc:format, tiff:Model).

  3. Why might a plain screenshot or graphic asset show no metadata at all when using this component?

    Show answer

    It likely lacks EXIF/TIFF metadata, unlike most camera photos.

  4. What two external API calls does WeatherModel make, and in what order?

    Show answer

    First Open-Meteo's geocoding API (city/country → latitude/longitude), then Open-Meteo's forecast API for current conditions at those coordinates.

  5. What Java HTTP client does WeatherModel use to make these calls?

    Show answer

    java.net.http.HttpClient, the built-in JDK 11+ client.

  6. What does the geocode() method do when a country is supplied alongside an ambiguous city name like "Cambridge"?

    Show answer

    It loops through the geocoding results looking for one whose country matches, rather than just blindly using the first result.

  7. Why is making a synchronous HTTP call inside WeatherModel's @PostConstruct flagged as a problem?

    Show answer

    Every page render then waits on a third-party API — slow, fragile if that API has an outage, and an easy way to get rate-limited.

  8. Which later module shows the production-correct fix for that synchronous-HTTP-call problem?

    Show answer

    Module 18, Sling Jobs — a scheduled background job fetches and caches the weather periodically instead.

  9. Even though ImageMetadataModel inherits its dialog from the core Image component, does it automatically inherit being allowed in a template's policy?

    Show answer

    No — it's a distinct resourceType (academy/components/imagemetadata) with its own entry in the policy's component list and has to be allowed explicitly.

  10. What field does an author fill in on the Weather component's dialog to disambiguate a city that exists in multiple countries?

    Show answer

    The optional country field.
