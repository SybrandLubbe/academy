Adobe Analytics Workspaces

Adobe Analytics is where all that tracking data becomes useful. Analysis Workspace is the primary analysis environment — a drag-and-drop canvas for building reports, discovering patterns, and sharing findings. This module gives you enough to be useful in a client meeting and to know when to call a dedicated analyst.

What you'll learn

  • Core vocabulary: Report Suites, Dimensions, Metrics, Segments
  • Navigating Analysis Workspace and building a Freeform Table
  • The most useful visualisations and when to use each
  • Attribution models — why the same data gives different numbers
  • Segments — filtering data without changing it
  • Scheduling and sharing reports with stakeholders

Core vocabulary

fundamental Analytics concepts — know these before any client meetingREPORT SUITE
  The data silo where your site's tracking data lands.
  Separate suite per brand. Always have: 1 prod + 1 dev suite.

DIMENSION    "What" — a categorical variable
  Page Name, Browser, Country, Marketing Channel, eVar1 (custom)
  A dimension has values: Page Name → "Home", "Checkout", "About Us"

METRIC       "How many" — a number
  Page Views, Visits, Unique Visitors, Revenue, event1 (custom)

SEGMENT      "Who" — a filter applied to a report
  "Mobile Users", "Visitors who purchased", "Sessions from Germany"

PAGE VIEW    One page load
VISIT        A session (30-min inactivity timeout)
VISITOR      A unique person (cookie-based); can have many Visits
📖 Why this code?

These four concepts (Dimension, Metric, Segment, Report Suite) are the building blocks of every Workspace report.

  • Dimension vs Metric: dimensions are rows ("Page Name"), metrics are columns ("Page Views"). All Freeform Tables follow this pattern.
  • Visits vs Visitors vs Page Views — the most frequently confused trio. Page Views counts loads. Visits counts sessions. Visitors counts unique people. One visitor can have many visits; one visit can have many page views.
  • eVar vs standard dimension — eVars are custom dimensions you populate via Tags. Standard dimensions (Browser, Country) are populated automatically by Analytics.

Navigating Analysis Workspace

Workspace layout — main areashttps://experience.adobe.com/analytics → Workspace → Create Project → Blank

LEFT SIDEBAR TABS:
  📊 Components     → all Dimensions, Metrics, Segments, Date Ranges
  📋 Panels         → drag onto canvas to structure a report
  📈 Visualisations → drag charts onto panels or Freeform Tables

CANVAS:
  Freeform Table    → drag Dimensions to rows, Metrics to columns
  Date picker       → top right of each Panel

TOOLBAR:
  Share             → live link or scheduled email
  Download          → CSV, PDF, Excel
📖 Why this code?

Workspace is entirely drag-and-drop — the sidebar categories are the key to finding what you need quickly.

  • Freeform Table is the default building block. Most other visualisations are derived from a Freeform Table.
  • Use the search box in the Components tab — a large implementation may have hundreds of custom eVars and events. Searching by label is far faster than scrolling.

Building a Freeform Table

step-by-step: top 10 pages in last 30 days1. Drag "Freeform Table" visualisation onto the canvas
2. From Components → Dimensions:
   Drag "Page" dimension to the table row area
   → 10 rows appear, ordered by most viewed
3. From Components → Metrics:
   Drag "Page Views" to first column
   Drag "Unique Visitors" to add a second column
4. Date range (panel header, top right): "Last 30 days"
5. Sort by Page Views (click column header)

BREAKDOWN:
  Right-click any row → Breakdown → choose second dimension
  e.g. break "Home" by "Browser" → which browsers did Home visitors use?

ROW FILTER:
  Funnel icon on a row → filter rows by dimension value
  e.g. show only pages whose names contain "checkout"
📖 Why this code?

Every element in a Freeform Table is interactive — right-clicking a row reveals breakdowns, visualisations, and filter options.

  • Breakdown adds a second dimension inside a row, answering "among people who viewed X, what Y did they use?" — replacing two separate reports.
  • Tables automatically recalculate when you change the date range or apply a segment — there's no "run query" button.

Visualisations — which to use

six visualisations and their use casesLINE CHART
  Trends over time (daily page views, weekly sessions)
  "Is engagement going up or down over the quarter?"

BAR / HORIZONTAL BAR
  Comparing values across categories
  "Which 5 pages had the most traffic this month?"

DONUT
  Part-to-whole (channel mix, device type breakdown)
  "What % of visits came from organic vs paid?"

FALLOUT
  Step-by-step conversion funnel — did sessions touch each step IN ORDER?
  "What % reached checkout after viewing a product?"

FLOW
  Path analysis — where did users go before/after a specific page?
  "What did people do after leaving the About Us page?"

COHORT TABLE
  Retention over time — of users acquired in period X, how many returned in Y?
📖 Why this code?

Choosing the right visualisation is half of good data communication — a line chart for category comparisons gives the wrong impression.

  • Fallout counts sessions that touched each step in order, but not necessarily consecutively — a user can visit 50 pages between Step 1 and Step 2 and still count. For strict consecutive steps, use "Sequential" segments.
  • Flow fans out in both directions: what came before and what came after a specific page. Excellent for discovering unexpected user paths that lead to conversion.

Attribution models

why the same conversion can produce completely different channel credit numbersUser journey: Organic Search → Email → Direct → £500 Purchase

LAST TOUCH (Analytics default):
  100% to "Direct"      — email gets zero credit

FIRST TOUCH:
  100% to "Organic"     — direct gets zero credit

LINEAR:
  33% each              — all touchpoints share equally

TIME DECAY:
  ~50% Direct, ~30% Email, ~20% Organic
  — more credit to channels closer to conversion

ALGORITHMIC (Attribution IQ):
  ML model trained on your conversion data
📖 Why this code?

Attribution is why two analysts can report different conversion numbers from the same data — neither is wrong; they're answering different questions.

  • Change the model on any metric: click the metric name in a Freeform Table → Attribution Model. This changes that column only, in that report — it doesn't affect raw data.
  • When a stakeholder says "email underperforms," ask which model they used. Email almost always looks better under Linear or Time Decay than Last Touch, because it typically assists conversions rather than closing them.

Segments — filtering without changing data

creating and applying segmentsCREATE:
  Components → Segments → + → New Segment
  Name: "Mobile Users"
  Container: Hit
  Rule: Mobile Device Type equals "Mobile Phone"

APPLY TO PANEL:
  Drag segment onto Panel header
  → All tables and charts in that panel show Mobile Users only

APPLY TO A SINGLE COLUMN:
  Drag onto a Freeform Table column header
  → That column = Mobile Users; others unchanged

COMPARE TWO SEGMENTS:
  Drag TWO segments onto a Panel header
  → Panel auto-splits for side-by-side comparison

SEQUENTIAL SEGMENT:
  Visitors who viewed a product page AND THEN visited checkout
  Container: Visitor
  Step 1: Page contains "product"
  THEN (not AND):
  Step 2: Page contains "checkout"
📖 Why this code?

Segments are non-destructive — they filter the view without changing the underlying data. Apply, remove, and change freely.

  • Container level — Hit filters individual page views; Visit includes all hits from a matching session; Visitor includes all sessions from users who ever matched. Container dramatically changes what data is included.
  • THEN vs AND: AND means both conditions in any order; THEN means Condition 1 must precede Condition 2. Always use THEN for funnel analysis.

Scheduling and sharing

sharing optionsSHARE → WORKSPACE USERS (live):
  Recipient sees live data, can interact.
  Requires an Adobe Analytics licence.

SCHEDULE → SEND FILE:
  Format: CSV / PDF / Excel
  Frequency: Daily / Weekly / Monthly
  Recipients: email addresses (no licence needed to receive)
  → Snapshot — data frozen at send time.

CURATE PROJECT:
  Choose which components are visible to recipients.
  Hides unused eVars and events — reduces confusion for non-analysts.
  Best for: handing a project to a client who wants self-service.
📖 Why this code?

Curation removes cognitive overload for non-analysts by showing only the dimensions, metrics, and segments relevant to their question.

  • Scheduled PDF is the most common executive deliverable. Set date range to "Previous Week" for automated weekly reports — it recalculates automatically each send.
  • Virtual Report Suites (VRS) are the enterprise self-service solution: a filtered view of the main suite with curated components, given to a team so they see only their product area's data.
Try it — build a real report Create a Workspace project with three panels:
  1. Traffic overview — Line chart of Page Views + Visits, last 30 days.
  2. Top pages — Freeform Table: Page dimension + Page Views metric. Break down the top 3 pages by Device Type.
  3. Mobile vs Desktop — Apply "Mobile Users" and "Desktop Users" segments to the same panel. Add Unique Visitors to each.
