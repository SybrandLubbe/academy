Sling Models

A Sling Model turns a Resource into a typed Java object you can use directly in a template or a servlet — the bridge between the repository tree from module 2 and the components you'll build in module 11. This module covers the basic shape of that bridge: what a model is, what adaptation means, and how content actually gets injected into one.

What you'll learn

  • The @Model annotation, and what "adaptable" and "adaptation" actually mean
  • The injectors you'll use constantly: @ValueMapValue, @ChildResource, @SlingObject, @Self, @Default
  • Required vs. optional injection, and why adaptTo() sometimes silently returns null
  • Deriving values with @PostConstruct, and exposing a model as JSON with @Exporter

Overview

Before models, components read content directly from a ValueMap or walked a Resource by hand inside the render script itself, mixing repository access with presentation logic. A Sling Model moves that access into a plain, testable Java class — the template asks the model for a typed value (a String, a List, a boolean) instead of reaching into the repository itself. Everything in this module builds toward one idea: a model is a small, declarative translation layer between "stuff in the repository" and "a Java object your code can actually work with."

01 · Sling Models & Adaptation

"Adaptation" is Sling's general-purpose mechanism for turning one kind of object into another related one — it's the same mechanism behind resource.adaptTo(ValueMap.class), and a Sling Model is simply a custom adapter target you define yourself. A model declares what it can adapt from (its adaptable) and, usually, which resource type it's tied to:

/aem-academy/core/src/main/java/biz/netcentric/academy/_05/TeaserModel.java (academy.core)package biz.netcentric.academy._05;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.DefaultInjectionStrategy;
import org.apache.sling.models.annotations.Exporter;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ChildResource;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;

import javax.annotation.PostConstruct;

@Model(
        adaptables = Resource.class,
        resourceType = "academy/components/teaser",
        defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL
)
@Exporter(name = "jackson", extensions = "json")
public class TeaserModel {

    @ValueMapValue
    private String title;

    @ValueMapValue
    private String description;

    @ChildResource
    private Resource image;

    private String shortDescription;

    @PostConstruct
    protected void init() {
        if (description != null && description.length() > 80) {
            shortDescription = description.substring(0, 80).trim() + "…";
        } else {
            shortDescription = description;
        }
    }

    public String getTitle() {
        return title;
    }

    public String getShortDescription() {
        return shortDescription;
    }

    public boolean hasImage() {
        return image != null;
    }
}

The adaptables value matters: Resource.class works wherever you have a resource — including adapting from inside another model — while SlingHttpServletRequest.class is only available during an actual request, but gives you request-specific things a bare resource can't, like selectors or request parameters.

02 · Injecting Content into a Model

Each field's (or constructor parameter's) annotation tells Sling Models exactly where to pull its value from. A handful of injectors cover almost everything you'll write:

  • @ValueMapValue — reads a property straight off the resource's ValueMap. By far the most common injector; this is what title and description use above.
  • @ChildResource — resolves a named child node as a Resource, or adapts it straight into another model in one step (used for image above).
  • @SlingObject — injects framework objects you already know: Resource, ResourceResolver, SlingHttpServletRequest, SlingHttpServletResponse.
  • @Self — injects the adaptable itself, typed as something else useful — most commonly used to pull in another model adapted from the exact same resource, the mechanism module 8 builds on for composing over Core Components.
  • @Default — pairs with another injector to supply a fallback (@Default(values = "Untitled")) when the underlying value is missing, instead of leaving the field null.

By default, every injected field is required: if Sling can't find a value for it, the whole model fails to instantiate and resource.adaptTo(TeaserModel.class) returns null — not a half-populated object. Setting defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL at the class level (as TeaserModel does above) flips that default, which is usually what you want for content fields that are genuinely optional, like a teaser's image. You can also mark an individual field optional without changing the class-wide default, by adding @Optional alongside its injector annotation (or @Required for the reverse, on a class set to optional by default).

Common pitfall adaptTo() returning null with no exception is the single most common Sling Models debugging trap. It almost always means a required field had nothing to inject. Enable debug logging on org.apache.sling.models.impl in the Felix console to see exactly which field failed.

Once content is injected, @PostConstruct is where you derive anything that isn't a direct 1:1 read — shortDescription above is built this way, after injection has already happened and every field is in its final state. And once a model has data worth handing to a client directly, @Exporter(name = "jackson", extensions = "json") is what made the .model.json selector work back in the Java Primer's exercises 3 and 5 — the model's getters become JSON fields, and anything you didn't expose with a getter simply isn't in the output.

Module 7 picks up the thread from here — adaptables in depth, injection style, deployment, and how a model relates to OSGi services and configuration even though it's never an OSGi component itself.

Try it Extend StudentModel from the Java Primer's exercise 3 with a @PostConstruct method that builds a fullName field from name and surname, then confirm it shows up at /content/academy/student.model.json.

Knowledge Check

Ten questions to ask students once they've finished this module — answers are hidden by default so you can quiz live before revealing them.

  1. Why do Sling Models exist — what problem do they solve compared to reading a ValueMap directly in a render script?

    Show answer

    They move repository access out of the render script into a plain, testable Java class — the template asks for a typed value instead of reaching into the repository itself.

  2. What does @ChildResource do, that's different from @ValueMapValue?

    Show answer

    It resolves a named child node as a Resource (or adapts it straight into another model), rather than reading a property off the current resource.

  3. What does @Self do, and which later module's pattern depends on it?

    Show answer

    It injects the adaptable itself, typed as something else useful — most commonly another model adapted from the same resource. Module 8's composition pattern for extending Core Components depends on it.

  4. By default, is an injected field required or optional? What happens if a required field can't be filled?

    Show answer

    Required by default; if it can't be filled, the whole model fails to instantiate and adaptTo() returns null, not a half-populated object.

  5. What does setting defaultInjectionStrategy = DefaultInjectionStrategy.OPTIONAL at the class level change?

    Show answer

    It flips the default so fields are optional unless marked otherwise — appropriate for content fields that are genuinely optional.

  6. adaptTo() returns null with no exception. What's the single most common cause, and how do you find out which field is at fault?

    Show answer

    A required field had nothing to inject; enable debug logging on org.apache.sling.models.impl in the Felix console to see exactly which field failed.

  7. What annotation makes a model's getters serializable as JSON via the .model.json selector?

    Show answer

    @Exporter(name = "jackson", extensions = "json").

  8. What does the adaptables value on @Model control?

    Show answer

    What kind of object the model can be created from — e.g. Resource.class vs SlingHttpServletRequest.class.

  9. Does Resource.class or SlingHttpServletRequest.class work in more contexts as an adaptable, and why?

    Show answer

    Resource.class — it's available wherever you have a resource, including adapting from inside another model, while a request adaptable only works during an actual HTTP request.

  10. TeaserModel builds a shortDescription field by truncating description to 80 characters. Which lifecycle annotation runs that logic after injection completes?

    Show answer

    @PostConstruct.
