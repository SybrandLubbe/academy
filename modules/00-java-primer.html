Java Primer for AEM

A condensed version of the team's Java Academy deck, with the generic exercises swapped for ones that build, deploy, and run against an actual AEM author instance. Use this before module 1 with anyone who needs a Java refresher rather than a first introduction.

What's here

  • A 34-slide condensed deck (down from the original 74) covering the same five sections: the basics, OOP, the Java API, exceptions, and Java 8/11
  • Five exercises, each rewritten to run on localhost:4502 instead of a standalone Java project
  • Full reference source for every exercise below, ready to drop into an AEM project's core bundle

Slides

Same structure and branding as the original deck, cut from 74 slides to 34. History, JAR/manifest internals, i18n/date formatting, and most of the nested-class and method-reference variations were trimmed — flag in the session if your group needs those restored.

Before you start

Every exercise in this curriculum assumes you have a local AEM author instance running at localhost:4502, and an AEM project checked out from the standard Maven Project Archetype. From here on, every file path given anywhere in this curriculum is the exact, full path from your project's root folder — no guessing, no "put it somewhere in core." If your checkout is named exactly aem-academy (the name used throughout this training), your folder structure looks like this:

project structure — memorize this, you'll use it constantly/aem-academy                    [academy-base-project-component]
│
├── all                          [academy.all]
│   └── the single content package that bundles every module
│       below into one install — this is what you actually deploy
│
├── core                         [academy.core]
│   └── src/main/java/...        all Java: Sling Models, OSGi
│       services, servlets, workflow steps, job consumers
│
├── ui.apps                      [academy.ui.apps]
│   └── src/main/content/jcr_root/apps/...
│       component definitions, dialogs, HTL scripts, clientlibs —
│       anything an author can drag onto a page
│
├── ui.apps.structure            [academy.ui.apps.structure]
│   └── editable template structure & page policies — not used
│       directly in these exercises, but this is where a real
│       project defines which components a template allows
│
├── ui.config                    [academy.ui.config]
│   └── src/main/content/jcr_root/apps/.../osgiconfig/...
│       OSGi configuration as deployable .cfg.json files
│
├── ui.content                   [academy.ui.content]
│   └── src/main/content/jcr_root/content/...
│       sample/seed content used to try things out
│
└── ui.frontend                  [academy.ui.frontend]
    └── a separate webpack-based front-end build for clientlib
        JS/CSS — not used in these exercises, which keep clientlibs
        simple and authored directly under ui.apps
Mental model The bracketed name next to each folder (academy.core, academy.ui.apps, and so on) is that module's Maven artifactId — you'll see it in each module's own pom.xml and in build output. These exercises only ever touch four of the seven folders: core, ui.apps, ui.content, and ui.config. ui.apps.structure and ui.frontend exist in every real AEM Archetype project and are described above so you recognize them, but nothing in this curriculum asks you to edit either.
  • The mvn clean install -PautoInstallSinglePackage profile working against your local instance, run from /aem-academy (the project root) — this builds every module listed above and deploys the result in one step
  • If your checkout uses a different root folder name or package, mentally substitute it everywhere you see /aem-academy and biz.netcentric.academy below
Common pitfall All five exercises register servlets or models against custom resource types under a project package. If a build deploys but a curl returns 404, check /system/console/components for the component first — it's almost always a registration property typo, not a missing deploy.

Exercise 1 — Build & Deploy to AEM

Maps to Compile and Run. The Java mental model is the same — source compiles to bytecode, a JVM runs it — but in an AEM project you don't call javac/java directly. Maven compiles your code into a bundle and installs it into the running JVM that's already inside AEM.

/aem-academy/core/src/main/java/biz/netcentric/academy/_01/HelloWorldServlet.java (academy.core)package biz.netcentric.academy._01;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.servlets.SlingSafeMethodsServlet;
import org.osgi.service.component.annotations.Component;

import javax.servlet.Servlet;
import javax.servlet.ServletException;
import java.io.IOException;

@Component(
        service = Servlet.class,
        property = {
                "sling.servlet.paths=/bin/academy/hello",
                "sling.servlet.methods=GET"
        }
)
public class HelloWorldServlet extends SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request, SlingHttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/plain");
        response.getWriter().write("Hello World!");
    }
}

Build and deploy, then confirm the bundle is active before testing the endpoint:

terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

# check it deployed: open in a browser
http://localhost:4502/system/console/bundles

# test it
curl http://localhost:4502/bin/academy/hello
Expected result Hello World! as plain text. If you get a 404, the servlet didn't register — check the bundle is Active first.

Exercise 2 — Service Interfaces in OSGi

Maps to Classes / Encapsulation / Interfaces. A GreetingService interface hides its implementation behind a contract — the same encapsulation idea from the slides, just expressed as an OSGi service rather than a plain class.

/aem-academy/core/src/main/java/biz/netcentric/academy/_02/GreetingService.java (academy.core)package biz.netcentric.academy._02;

public interface GreetingService {
    String greet(String name);
}
/aem-academy/core/src/main/java/biz/netcentric/academy/_02/GreetingServiceImpl.java (academy.core)package biz.netcentric.academy._02;

import org.osgi.service.component.annotations.Component;

@Component(service = GreetingService.class)
public class GreetingServiceImpl implements GreetingService {

    @Override
    public String greet(String name) {
        if (name == null || name.isBlank()) {
            name = "stranger";
        }
        return "Hello, " + name + "! Welcome to the AEM Academy.";
    }
}
/aem-academy/core/src/main/java/biz/netcentric/academy/_02/GreetingServlet.java (academy.core)package biz.netcentric.academy._02;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.servlets.SlingSafeMethodsServlet;
import org.osgi.service.component.annotations.Component;
import org.osgi.service.component.annotations.Reference;

import javax.servlet.Servlet;
import javax.servlet.ServletException;
import java.io.IOException;

@Component(
        service = Servlet.class,
        property = {
                "sling.servlet.paths=/bin/academy/greet",
                "sling.servlet.methods=GET"
        }
)
public class GreetingServlet extends SlingSafeMethodsServlet {

    @Reference
    private GreetingService greetingService;

    @Override
    protected void doGet(SlingHttpServletRequest request, SlingHttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/plain");
        response.getWriter().write(greetingService.greet(request.getParameter("name")));
    }
}
terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

curl "http://localhost:4502/bin/academy/greet?name=World"
Try it with students Have them change GreetingServiceImpl without touching GreetingServlet at all — redeploy and the servlet picks up the new behavior automatically. That's the point of coding to the interface.

Exercise 3 — Collections in a Sling Model

Maps to Collections. A multi-value JCR property becomes a List<String> the moment it's read into Java — this is usually a student's first encounter with collections in a real AEM context.

/aem-academy/core/src/main/java/biz/netcentric/academy/_03/StudentModel.java (academy.core)package biz.netcentric.academy._03;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.Exporter;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;

import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

@Model(adaptables = Resource.class, resourceType = "academy/components/student")
@Exporter(name = "jackson", extensions = "json")
public class StudentModel {

    @ValueMapValue
    private String name;

    @ValueMapValue
    private String surname;

    @ValueMapValue
    private String[] subjects;

    public String getName() {
        return name;
    }

    public String getSurname() {
        return surname;
    }

    public List<String> getSubjectsSorted() {
        List<String> sorted = new ArrayList<>(
                List.of(subjects != null ? subjects : new String[0]));
        sorted.sort(Comparator.naturalOrder());
        return sorted;
    }
}

Create a test content node under CRXDE Lite (or via the package manager) at /content/academy/student with sling:resourceType = academy/components/student, plus name, surname, and a multi-value string subjects property.

terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

curl http://localhost:4502/content/academy/student.model.json
Expected result A JSON object with name, surname, and subjectsSorted as an alphabetically sorted array — confirming the model adapted the resource and the collection logic ran.

Exercise 4 — Handling Errors in a Servlet

Maps to Declared vs. Runtime Exceptions. Rather than letting an exception crash a thread, a backend endpoint should catch it and turn it into a meaningful HTTP response — this is the most common exception-handling pattern students will actually write on the job.

/aem-academy/core/src/main/java/biz/netcentric/academy/_04/ValidationServlet.java (academy.core)package biz.netcentric.academy._04;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.servlets.SlingSafeMethodsServlet;
import org.osgi.service.component.annotations.Component;

import javax.servlet.Servlet;
import javax.servlet.ServletException;
import java.io.IOException;

@Component(
        service = Servlet.class,
        property = {
                "sling.servlet.paths=/bin/academy/validate",
                "sling.servlet.methods=GET"
        }
)
public class ValidationServlet extends SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request, SlingHttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("application/json");
        try {
            validateUser(request.getParameter("username"));
            response.getWriter().write("{\"status\":\"ok\"}");
        } catch (InvalidUserException e) {
            response.setStatus(400);
            response.getWriter().write("{\"error\":\"" + e.getMessage() + "\"}");
        }
    }

    private void validateUser(String username) throws InvalidUserException {
        if (username == null || username.isBlank()) {
            throw new InvalidUserException("Username must not be empty");
        }
        if ("admin".equalsIgnoreCase(username)) {
            throw new InvalidUserException("'admin' is a reserved username");
        }
    }

    /** Declared (checked) exception - callers must handle it explicitly. */
    static class InvalidUserException extends Exception {
        InvalidUserException(String message) {
            super(message);
        }
    }
}
terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

curl -i "http://localhost:4502/bin/academy/validate?username=admin"
curl -i "http://localhost:4502/bin/academy/validate?username=jdoe"
Try it with students Add a third rule (e.g. usernames under 3 characters) and a matching message. The goal is to see the same try/catch shape handle a new failure case without restructuring the method.

Exercise 5 — Streams Over Page Resources

Maps to Lambdas & Streams. Walking a page's children and pulling out their titles is one of the most common things backend code does in AEM — and it reads naturally as a stream pipeline.

/aem-academy/core/src/main/java/biz/netcentric/academy/_05/ChildPagesModel.java (academy.core)package biz.netcentric.academy._05;

import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.Exporter;
import org.apache.sling.models.annotations.Model;

import java.util.List;
import java.util.Objects;
import java.util.stream.Collectors;
import java.util.stream.StreamSupport;

@Model(adaptables = Resource.class, resourceType = "academy/components/page")
@Exporter(name = "jackson", extensions = "json")
public class ChildPagesModel {

    private final Resource resource;

    public ChildPagesModel(Resource resource) {
        this.resource = resource;
    }

    public List<String> getChildPageTitles() {
        return StreamSupport.stream(resource.getChildren().spliterator(), false)
                .map(child -> child.getChild("jcr:content"))
                .filter(Objects::nonNull)
                .map(content -> content.getValueMap().get("jcr:title", content.getName()))
                .sorted()
                .collect(Collectors.toList());
    }
}

Point this at any existing page in your content tree that has child pages — set sling:resourceType = academy/components/page on its jcr:content node, or test against a copy if you don't want to touch real content.

terminal, run from /aem-academymvn clean install -PautoInstallSinglePackage

curl http://localhost:4502/content/academy/page.model.json
Try it with students Swap .sorted() for a .filter() that only keeps published pages (check jcr:content for a cq:lastReplicationAction property equal to Activate). It's a small change that shows how naturally another pipeline stage slots in.
